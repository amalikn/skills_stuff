## Transcript

### 0:00 Introduction

In this tutorial, your agent works through your first task with you, and keeps the task in Pad up to date as it goes. Keep the Tasks board open in your browser. You'll see the task move across it as the agent works.

### 0:15 Pick the task

We pick up where the last tutorial ended: the agent found TASK-6, the one task that's ready, and asked whether to start. Say yes, and add anything it should know about the work.

### 0:29 Start the work

First it reads the task, and the conventions for building. Here that's one rule: new code gets a test, written with Vitest. Then it moves the task to in progress, with a comment that says what it's starting. On the board, the card moves to In Progress by itself.

### 0:49 Decide together

Now it reads the code it will change. The code in this video is a short example, to show the flow. When a choice is yours to make, it asks. Your answer is saved on the task as a decision, so the reason outlives this chat.

### 1:06 Test and finish

It writes the change and a test. Before a task is done, your conventions say to run npm test, so it does, and the tests pass. Then it marks the task done, with a comment saying what changed and how it was checked. The card moves to Done.

### 1:26 Check the trail

Open the task to see its trail. Each comment carries your agent's name, next to yours. Under History, the decision sits with the status change, along with its reason.

### 1:40 What you have now

You now have your first task done, with its decision and test results recorded in Pad. Next, plan something bigger. In the same session, type /pad plan online payments. The agent loads the plan playbook, and checks your workspace first. The next tutorial picks up from here.
