# Archcore Routing Pattern

Use Archcore as structured durable project truth when `.archcore/` exists.

When `skill-ai-it` runs in `bootstrap`, `navigation-add`, or `refresh` mode and the `archcore` CLI is available, initialize `.archcore/` with `archcore init` if it is missing.

## Core principle

`skill-ai-it` uses a **report-first** approach:

- `bootstrap` and `refresh` emit `ARCHCORE_PROMOTION_CANDIDATES.md` after `archcore init`. No `.archcore/` content files are created.
- `promote` is the **only** mode that writes `.archcore/` content files (adr, rules, specs, guides, plans).
- `promote` also writes `.archcore/README.md` as the durable index, carries the *never promote* reasoning into it, and then **deletes** `ARCHCORE_PROMOTION_CANDIDATES.md`. The candidates file is a
  queue that exists between surfacing and promoting — it lives at the repo root, which `bootstrap` and `refresh` both rewrite, so nothing durable can be kept in it.

Do not populate `.archcore/` content during bootstrap or refresh. Surface candidates; require explicit authorization to promote.

## Source mapping

| Content | Archcore target |
|---|---|
| Final architecture decision | `.archcore/adr/` |
| Durable project/agent rule | `.archcore/rules/` |
| Technical/design contract | `.archcore/specs/` |
| Operating procedure | `.archcore/guides/` |
| Implementation plan | `.archcore/plans/` |
| Reference material | `.archcore/docs/` |
| Open proposal | `.archcore/rfc/` |
| Early idea | `.archcore/ideas/` |

## Extraction heuristics

Apply these heuristics when scanning governance files to build `ARCHCORE_PROMOTION_CANDIDATES.md`.

### `.archcore/adr/` candidates

**Source files:** `ARCHITECTURE.md`, `SCRATCHPAD.md` (KEEP blocks), `memory-bank/decisionLog.md`, `AGENTS.md`, `ROADMAP.md`

**Heading signals:** Decision, Key decisions, ADR, Accepted decision, Architecture decision, Approach chosen

**Language signals:** "we will", "chosen approach", "accepted", "decided", "source of truth is", "rationale:", "this approach was selected because"

**Quality gate:** candidate must have a subject + rationale + affected area. If rationale is missing, include with `confidence: low`.

### `.archcore/rules/` candidates

**Source files:** `AGENTS.md`, `CONVENTIONS.md`, `AI_NAVIGATION.md`, governance sections of `README.md`

**Language signals (normative):** must, never, always, do not, treat X as source of truth, agents must, this file is authoritative, all agents

**Strong candidates:** managed policy blocks (marked with `<!-- BEGIN -->` / `<!-- END -->` comments), explicit rule lists

**Exclude:** rules inherited verbatim from a parent or global `AGENTS.md` — only promote rules specific to the target project.

### `.archcore/specs/` candidates

**Source files:** `ARCHITECTURE.md`, `CONVENTIONS.md`, `docs/*.md`

**Signals:** stable contracts, schema definitions, interface boundaries, data flow invariants, component interaction contracts

**Exclude:** narrative architecture description without a constraint or boundary statement.

### `.archcore/guides/` candidates

**Source files:** `README.md`, `docs/*.md`, procedure sections of `AGENTS.md`

**Signals:** stable, reusable multi-step procedures with numbered steps and expected outcomes

**Exclude:** one-off troubleshooting notes, session-specific instructions, anything tied to a single past incident.

### `.archcore/plans/` candidates

**Source files:** `ROADMAP.md`, approved phase plan docs under `docs/`

**Signals:** accepted/approved implementation plans with phases, milestones, and sequencing

**Exclude:** draft plans, completed/obsolete phases, speculative roadmap items.

## Exclusion table

| Category | Rationale |
|---|---|
| `CHANGELOG.md` | History and corroboration only — not a source of durable truth. Never extract directly. |
| Generated files (`.ai-context/`, `graphify-out/`, `repomix-output.md`) | Rebuildable outputs — not canonical. |
| TODOs and unresolved questions | Transient. Resolve before promoting. |
| Session notes (unmarked SCRATCHPAD sections) | Temporary. Only KEEP-marked blocks are candidates. |
| Rules inherited from parent/global AGENTS.md | Already governed upstream. Avoid duplication. |
| Draft plans and speculative roadmap items | Not accepted/approved. |
| Completed or obsolete roadmap items | History only. |
| One-off troubleshooting or incident-specific notes | Not reusable as operating procedures. |

## Completion gate

Before completing `bootstrap`, `navigation-add`, or `refresh` when `.archcore/` exists:

- Confirm `ARCHCORE_PROMOTION_CANDIDATES.md` exists in the target root, or explicitly report why it was not created or updated.
- Read back or section-check the candidate report before the final response.
- Confirm no `.archcore/adr/`, `.archcore/rules/`, `.archcore/specs/`, `.archcore/guides/`, or `.archcore/plans/` content files were written outside `promote` mode.
- If the project uses Repomix, include `ARCHCORE_PROMOTION_CANDIDATES.md` in generated context or explicitly report why it was excluded.

## Rules

- Do not treat scratchpad notes as durable truth unless marked `KEEP`.
- `archcore init` is allowed when the CLI is available and `.archcore/` is missing.
- Do not directly edit Archcore content files unless explicitly authorized.
- Prefer proposing Archcore changes first.
- If `.archcore/` conflicts with README/roadmap/scratchpad, Archcore wins unless marked draft.
- Do not promote rules already governed by a parent or global `AGENTS.md` — avoid duplicating upstream policy.
- Do not extract from generated files (`.ai-context/`, `graphify-out/`, `repomix-output.md`).
- `promote` is the **only** mode that creates `.archcore/` content files. Bootstrap and refresh emit the candidates report only.
