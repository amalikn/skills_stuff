## Working rules

- Code follows skill-coder (`/Volumes/Data/_ai/_skills/skills_stuff/specialists/project/skill-coder/SKILL.md`), invoked before any script is added or changed (operator, 2026-10-20 and 2026-10-27):
  purpose header with usage and safety, Args/Returns/Raises docstrings, two-space indent, timeouts on every call, `--apply` on every write, tests, measured runtime.
- Recipes call `{{py}}` (the working-cache venv) and depend on `_require-venv`; never a bare interpreter. The venv and runtime state never live in this folder.
- Durable decisions, rules, contracts, procedures and the pilot plan are indexed in `.archcore/` ([.archcore/index.guide.md](.archcore/index.guide.md)) as pointer
  documents; they outrank this file's prose where they differ, and their canonical text stays in `references/` (operator, 2026-10-27).
- `references/` is where rules change. `docs/` sources are kept verbatim; a correction to a source is made in the reference that consolidates it, citing the section.
- A behaviour claim about Vikunja, Claude Code or Codex is labelled `UNVERIFIED` until observed on the installed version, then recorded with the version and a capture under `documents/`.
- Every markdown file except `readme.md`, `SKILL.md` and `CLAUDE.md` carries the governance front matter (Title, Category, Status, Authority, Scope, Last reviewed, Summary); every new file gets a row
  in [docs/catalog.md](docs/catalog.md) (operator, 2026-10-27: "add frontmatter, catalog them properly").
- One blank line follows the closing `---` of the front matter (operator, 2026-10-27: "there should be a line gap after the frontmatter").
- Naming (operator, 2026-10-27): folders `goal-guard...`; documents and Python files `goal_guard...`; markdown filenames lower case except tool-mandated `SKILL.md`, `AGENTS.md`, `CLAUDE.md`. In prose the name is written "Goal Guard" (operator, 2026-10-27: "GoalGuard replace with Goal Guard ... in all files");
  identifiers (`GoalGuardError`), file names (`goal_guard`) and the snapshot format name (`goalguard-snapshot-tasks`) keep their spelling, and verbatim sources in `docs/` and `documents/` are not changed.
- No secrets, tokens, customer identifiers, or APN content in `me` material (or the reverse) in pack files. Vikunja tokens live in KeePassXC.
- Operator decisions are recorded with date and source ("operator, YYYY-MM-DD") in the reference that applies them and in [changelog.md](changelog.md).

## Cross-project write-back trigger

Any session, in any project, that assessed a proposal, ranked work, traced a milestone, wired a Goal Guard hook or read Vikunja for Goal Guard writes what it learned back here before closing: a dated
Learned entry in the focused reference plus one line under `## Unreleased` in [changelog.md](changelog.md), read back and committed (format in
[references/evolution-and-write-back.md](references/evolution-and-write-back.md)). If this source is not writable,
the entry waits in the project under `## skill-goal-guard write-back candidates`. A project's own facts stay in that project.

## Before calling work done

- `just check` passes (fix the code, not the check).
- `SKILL.md` routes every reference; `docs/catalog.md` lists every file; no broken relative links.
- A `changelog.md` line under `## Unreleased` for any change; the write-back contract for any learning.
