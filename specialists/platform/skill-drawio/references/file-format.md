## Skeleton

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- GENERATED by ... (optional banner, see data-first-diagrams.md) -->
<mxfile host="my-generator" type="device" compressed="false">
  <diagram id="overview" name="Overview">            <!-- one per page (tab) -->
    <mxGraphModel grid="1" gridSize="10" page="0" ...>
      <root>
        <mxCell id="0"/>                              <!-- root container, no parent -->
        <mxCell id="1" parent="0"/>                   <!-- default (base) layer -->
        <mxCell id="L-thick" value="Thick arrows" parent="0"/>   <!-- an extra layer -->
        ... vertices and edges, each with parent = a layer or group id ...
      </root>
    </mxGraphModel>
  </diagram>
  <diagram id="flow-1" name="1. First flow"> ... </diagram>
</mxfile>
```

`<mxfile>` holds one `<diagram>` per page; each page holds one `<mxGraphModel>` with one `<root>` [C-D04]. The `diagram` `id` is what page links point at; `name` is the tab label. Coordinates have
their origin at the top left, x to the right, y down.

## Root cells and layers

- Cell `0` is the root container and has no parent; cell `1` (parent `0`) is the default layer. Both are always required [C-D04].
- A layer is an `mxCell` with `parent="0"` and no `vertex` or `edge` attribute; its `value` is the name shown in the Layers panel [C-D05].
- Every shape or edge names a layer (or a group inside one) as its `parent`; a cell sits on exactly one layer. Edges may join shapes on different layers.
- Layer order in the file is stacking order: a later layer draws over an earlier one, and a shape cannot go behind a shape on a lower layer.
- `drawio.mxfile.Page.xml()` writes declared layers right after cells `0` and `1`, before any content, and the UNC tests assert that order. The official documents do not say a layer must come before the
  cells that name it; treat "right after the root cells" as the safe convention, not a documented requirement [C-D05].
- The CLI's `--layers` option selects layers by index, where index 0 is the base layer `1` ([export-and-self-review.md](export-and-self-review.md)).

## Vertices, UserObject, links and tooltips

A plain vertex is an `mxCell` with `vertex="1"`, a `value` (the label), a `style`, a `parent`, and an `mxGeometry` child with `x`, `y`, `width`, `height` and `as="geometry"`.

A cell with extra attributes (a link, a tooltip, custom data) is wrapped: the `UserObject` (or `object`, the two are interchangeable) carries the `id`, the `label` (instead of `value`) and the custom
attributes; the inner `mxCell` carries style, parent and geometry and has no id of its own [C-D06].

```xml
<UserObject id="box-api" label="&lt;b&gt;API&lt;/b&gt;" link="data:page/id,flow-1" tooltip="Opens flow 1">
  <mxCell style="rounded=1;whiteSpace=wrap;html=1;" vertex="1" parent="1">
    <mxGeometry x="40" y="80" width="200" height="60" as="geometry"/>
  </mxCell>
</UserObject>
```

- A link to another page of the same file is `data:page/id,<diagram id>` [C-D07]. Ordinary URLs work too.
- A reader that looks cells up by id must read both element kinds: `mxCell` elements with an `id`, and `UserObject`/`object` elements (taking the inner `mxCell` for style, parent and geometry)
  [C-D06].
- `placeholders="1"` on a UserObject substitutes `%attribute%` in its label; leave it off unless used.

## HTML labels

With `html=1` in the style, the label is HTML (`<b>`, `<i>`, `<br>`, `<font>`, and similar), and that HTML is XML-escaped inside the attribute [C-D08]. Put `whiteSpace=wrap` beside it so draw.io wraps
text inside the shape.

`drawio.mxfile.label()` builds such labels from plain lines: it HTML-escapes each line, turns `**bold**`, `*italic*` and `` `code` `` spans into `<b>`, `<i>` and a Courier New `<font>`, joins lines with
`<br>`, and drops empty lines (use the en space `BLANK` for a visible gap). `Page` then escapes the whole label again as an XML attribute. Escaping twice is correct: once for HTML, once for XML.

## Edges: waypoints and pinned ports

An edge is an `mxCell` with `edge="1"`, `source` and `target` ids, and an `mxGeometry` with `relative="1"`. Waypoints are `mxPoint` elements inside `<Array as="points">` in that geometry, in page (or
parent) coordinates [C-D09].

The ends are pinned with fractions of each box: `exitX`, `exitY` on the source and `entryX`, `entryY` on the target, each from 0 (left or top) to 1 (right or bottom) [C-D10]. Add
`exitPerimeter=0;entryPerimeter=0` so draw.io uses those exact points rather than projecting them onto the shape's perimeter.

```xml
<mxCell id="e1" value="" edge="1" parent="L-thick" source="box-a" target="box-b"
        style="edgeStyle=orthogonalEdgeStyle;html=1;endArrow=block;endFill=1;strokeWidth=4;jumpStyle=arc;jumpSize=7;exitX=1;exitY=0.5;entryX=0;entryY=0.25;exitPerimeter=0;entryPerimeter=0;">
  <mxGeometry relative="1" as="geometry">
    <Array as="points"><mxPoint x="300" y="110"/><mxPoint x="300" y="215"/></Array>
  </mxGeometry>
</mxCell>
```

`drawio.mxfile.Page.route()` takes the full polyline (first point on the source's border, last on the target's), writes the inner points as waypoints, and computes the four fractions from the end points,
so the drawn line is exactly the polyline the audits checked.

An edge with no source or target cell needs `sourcePoint` and `targetPoint` `mxPoint` elements in its geometry. Line hops at crossings are `jumpStyle` (`arc`, `gap`, `sharp`, `line`) and `jumpSize`
(default 6), and `jumpSize` is the hop's full width [C-D14].

## Groups and containers

A child's geometry is relative to its parent group or container, not to the page [C-D13]. A reader computing page positions adds each ancestor's `x` and `y` in turn
([reading-drawings.md](reading-drawings.md)). An edge's waypoints are relative to the edge's own parent in the same way. A generator that wants simple audits keeps every cell's parent a layer, so all
coordinates are page coordinates; UNC's renderer does this and draws "groups" as plain boxes behind their members.

## Compressed and uncompressed pages

A page is stored in one of two ways [C-D11]:

- **Uncompressed**: the `<diagram>` element contains an `<mxGraphModel>` child. `compressed="false"` on `<mxfile>`.
- **Compressed**: the `<diagram>` element contains text only. Encoding is URL-encode the model XML (`encodeURIComponent`), then raw deflate (no zlib header), then base64. Decoding reverses it:
  base64-decode, raw inflate, URL-decode.

In Python, raw deflate means `wbits=-15`:

```python
import base64, urllib.parse, zlib

def decode_page(text: str) -> str:
    """Compressed <diagram> text to mxGraphModel XML."""
    return urllib.parse.unquote(zlib.decompress(base64.b64decode(text.strip()), -15).decode())

def encode_page(model_xml: str) -> str:
    """mxGraphModel XML to compressed <diagram> text (what the desktop app writes when compression is on)."""
    c = zlib.compressobj(9, zlib.DEFLATED, -15)
    return base64.b64encode(c.compress(urllib.parse.quote(model_xml).encode()) + c.flush()).decode()
```

`urllib.parse.quote` and JavaScript's `encodeURIComponent` escape slightly different character sets; both decode correctly with `unquote`, which is all a reader needs.

Generators write uncompressed pages: they diff in review and a drift check can compare them byte for byte [C-D12]. The official style reference tells generators the same. The desktop app reads both
forms; files saved by older versions or other tools are often compressed, so a reader must handle both. In draw.io desktop 32.5.5, `-x -f xml` without `-u` wrote uncompressed pages for an uncompressed
input (observed 2026-10-19).

## Generator rules

| Rule                                                                                 | Why                                                                |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Cells `0` and `1` first, then layers, then content                                   | Required root cells; layers before their content is the safe order |
| Unique ids across the file                                                           | Links, edges and the CLI's layer selection rely on them            |
| `html=1;whiteSpace=wrap;` on labelled shapes                                         | HTML formatting and wrapping inside the shape                      |
| Every edge has `source`, `target`, waypoints and pinned fractions with perimeter off | The drawn line is the route the generator checked                  |
| Style strings end with `;`                                                           | Matches what draw.io writes; appending pinned ports stays valid    |
| `compressed="false"`                                                                 | Diffs and drift checks                                             |
| Fixed cell order and number formatting                                               | Deterministic output                                               |
