## Role and non-goals

This skill holds how the operator's projects draw with draw.io: diagrams are data first (a YAML map is the source; the drawing is rendered from it and never edited by hand), routed and audited by
code, exported and looked at before they are shown. It ships the engine that does this (packages `scripts/drawio/` and `scripts/flowmap/`), first built for unified-network-controller's flow map and
promoted here on 2026-10-19.

Non-goals: it holds no facts about the systems a diagram shows (the domain skill does), it does not decide a project's components or flows, and it never authorises a write outside the project's own
drawing files.

## Orient first

1. **Is the drawing generated or hand-made?** A file with the `GENERATED by` banner is rendered from its map: change the map and rerender. A drawing a person edited is source: patch or append only,
   keep a backup, never regenerate over it ([references/data-first-diagrams.md](references/data-first-diagrams.md)).
2. Read the project's own rules and its wrapper (for example a `scripts/render/*.py` that holds its drawing profile) before this skill; the project's rules outrank it.
3. Find the closing check (`just check`) and the drift check it runs; run catalogued tasks only.
4. For code in this pack or a project's wrapper, apply skill-coder's rules (module and function sizes, docstrings, timeouts, write gates).

## The pack's tools

Stdlib only (PyYAML at the edge, to read a map). Runnable front ends sit at the top of `scripts/`; the library is in two packages. Catalogue with inputs, outputs and safety:
[scripts/README.md](scripts/README.md).

| Entry point                  | What it does                                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------- |
| `scripts/render_flowmap.py`  | Validate a flow map and render it (`--write`), report drift, list flows, or audit the layout |
| `scripts/drawio_export.py`   | Export pages (counted from 1) and layers to PNG/SVG with the desktop app, under a timeout    |
| `scripts/drawio_read.py`     | Print an existing drawing's boxes and connections (compressed pages decoded); read-only      |
| `scripts/yaml_list_patch.py` | Add values to flow-style lists in a YAML map without losing comments; plan, then `--apply`   |

| Package            | Modules                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| `scripts/drawio/`  | `mxfile` (build pages and files), `audit` (layout audits), `route` (tracks, ports, untwist), `read`, `export` |
| `scripts/flowmap/` | `profile`, `model`, `overview_layout`, `overview`, `e2e_grid`, `e2e`, `pages`                                 |

## Using the flow-map engine in a project

- **New project:** write `flows.yaml` against [schemas/flowmap.schema.json](schemas/flowmap.schema.json) (copy and narrow it), add an optional `drawing:` block, then `render_flowmap.py --map <map>
  --write` and wire `render_flowmap.py --map <map>` (drift check) into `just check`. The worked example is [examples/shop/flows.yaml](examples/shop/flows.yaml) (`just example`).
- **Project with its own constants:** a thin wrapper builds a `flowmap.profile.Profile` and calls `flowmap.pages.render` / `evaluate`, loading the pack through the project's one seam to the skills
  (unified-network-controller: `wc-local/scripts/common/skill_paths.py`).
- A refactor of the engine must leave every consumer's drawing byte-identical; prove it with the before and after files.

## Standing rules

- A generated drawing carries the banner and is never hand-edited; a hand-made drawing is never regenerated over.
- Every arrow on a routed page has explicit waypoints, and `drawio.audit.page_audit()` reports nothing before the drawing ships.
- Export, crop, trace every arrow and fix before showing a drawing; never send an unreviewed first render.
- Every subprocess (the draw.io CLI) has a timeout; a write takes `--write` or `--apply`.

## Standing write-back contract

Touching this skill's domain, invoked or not, engages its write-back: a session in any project that drew, rendered, exported or read a draw.io file owes, at closeout, a dated Learned entry in the
reference a future reader would open plus one CHANGELOG line under `## Unreleased`, read back and committed in `skills_stuff`. When this source cannot be written, park the entry in the project under
`## skill-drawio write-back candidates`; skill-coder's `scripts/write_back.py --project-root <project> --skill skill-drawio` finds parked entries for the next engagement to promote. Format and
classes: [references/evolution-and-write-back.md](references/evolution-and-write-back.md).
