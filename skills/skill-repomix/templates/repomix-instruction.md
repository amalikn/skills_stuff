# Repository Interpretation Rules

1. Treat project governance files as operational policy.
2. Treat architecture and navigation files as authority maps.
3. Prefer documents marked `CURRENT AUTHORITATIVE`.
4. Use `CURRENT SUPPORTING` only as supporting evidence.
5. Do not derive current state from `SUPERSEDED`, historical, archived, or generated material.
6. Do not modify cache, data, runtime, generated, backup, or rollback paths unless explicitly requested.
7. Cite repository paths and line numbers.
8. Distinguish verified facts, inferred conclusions, and unresolved assumptions.
9. Read the smallest relevant file set before proposing changes.
10. Preserve repository governance.
