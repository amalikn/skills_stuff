## Design Principle

This tool accepts CSVs from any supplier or billing system. It does not require source files
to use specific column names. Instead, a **column mapping file** (`mapping.yaml`) bridges
whatever names the source CSV uses to the canonical field names defined here.

The canonical schema is fixed. The mapping is per-supplier and user-confirmed.

---

## How Column Mapping Works

### First run with a new CSV

1. `validate_inputs.py` scans the source CSV column names.
2. For each canonical required field, it tries heuristic patterns (listed below) to suggest
   a source column.
3. Suggestions with low confidence are flagged explicitly — never silently assumed.
4. The validator prints a draft `mapping.yaml` and asks the user to confirm or correct it.
5. Once confirmed, the mapping is saved alongside the CSVs and reused on every subsequent run.

### Subsequent runs

1. The validator reads the existing `mapping.yaml`.
2. If a required canonical field has no mapping entry, it fails with a clear message naming
   the missing field.
3. If the mapped source column is absent from the CSV, it fails and names the column.
4. No silent fallback to heuristics once a mapping file exists.

### Mapping file format

```yaml
# mapping.yaml
# Maps source CSV column names → canonical field names.
# Generated by validate_inputs.py on first run. Edit and confirm before use.

version: "1"
created: "2026-05-21"
source_type: supplier_invoice   # supplier_invoice | sales_billing | rate_card | service_map

field_mappings:
  invoice_number:         "Invoice Number"
  invoice_date:           "Invoice Date"
  billing_period_start:   "Service Period Start"
  billing_period_end:     "Service Period End"
  supplier_service_id:    "AVC ID"
  amount_ex_tax:          "Amount Ex GST"
  # Optional — omit if not present in source:
  service_type:           "Product Type"
  description:            "Charge Description"
  tax_amount:             "GST Amount"
```

A separate `mapping.yaml` is used per source type (supplier invoice, sales/billing, rate card).

### Legend

| Symbol | Meaning |
|---|---|
| **R** | Required — analysis cannot proceed without this field |
| **O** | Optional — used when present; omitted when absent |

### Source Type: `supplier_invoice`

Supplier-issued invoice lines — what we are charged by the upstream provider.

| Canonical Field | R/O/D | Type | Description |
|---|---|---|---|
| `invoice_number` | R | string | Unique identifier on the supplier invoice |
| `invoice_date` | R | date | Date the invoice was issued |
| `billing_period_start` | R | date | First day of the billing period covered |
| `billing_period_end` | R | date | Last day of the billing period covered |
| `supplier_service_id` | R | string | Supplier's identifier for the service line (e.g. AVC ID, CVC ID, circuit ID) |
| `amount_ex_tax` | R | decimal | Charge amount excluding tax, in AUD |
| `service_type` | O | string | Human-readable service category (e.g. NBN Fibre, Copper, Wireless) |
| `description` | O | string | Line-item description from the invoice |
| `quantity` | O | decimal | Unit count for usage-based charges |
| `unit_price_ex_tax` | O | decimal | Per-unit price excluding tax |
| `tax_amount` | O | decimal | Tax component (GST) |
| `amount_inc_tax` | O | decimal | Total charge including tax |
| `supplier_account_ref` | O | string | Supplier's reference for our account |
| `po_number` | O | string | Purchase order reference if present |

**Heuristic detection patterns** (tried in order when no mapping exists):

| Canonical Field | Patterns to try (case-insensitive substring match) |
|---|---|
| `invoice_number` | `invoice no`, `invoice number`, `invoice#`, `inv no`, `inv_no` |
| `invoice_date` | `invoice date`, `inv date`, `date issued`, `issue date` |
| `billing_period_start` | `period start`, `service start`, `from date`, `start date`, `billing from` |
| `billing_period_end` | `period end`, `service end`, `to date`, `end date`, `billing to` |
| `supplier_service_id` | `avc id`, `avc`, `cvc id`, `circuit id`, `service id`, `nbn id`, `port id` |
| `amount_ex_tax` | `amount ex`, `ex gst`, `ex tax`, `net amount`, `charge ex`, `subtotal` |
| `service_type` | `product type`, `service type`, `product`, `plan`, `technology type` |
| `description` | `description`, `charge description`, `line item`, `detail` |
| `quantity` | `qty`, `quantity`, `units`, `count` |
| `unit_price_ex_tax` | `unit price`, `rate`, `unit cost`, `price ex` |
| `tax_amount` | `gst`, `tax`, `vat`, `gst amount` |
| `amount_inc_tax` | `amount inc`, `inc gst`, `total`, `gross amount` |

| `customer_id` | R | string | Internal customer identifier |

| `our_service_id` | R | string | Our internal identifier for the service (links to supplier_service_id via service map) |
| `revenue_ex_tax` | R | decimal | Revenue charged to customer excluding tax, in AUD |
| `customer_name` | O | string | Customer display name |
| `supplier_service_id` | O | string | Supplier's ID if tracked in billing system |
| `service_type` | O | string | Service category |
| `description` | O | string | Billing line description |
| `quantity` | O | decimal | Unit count |
| `unit_price_ex_tax` | O | decimal | Per-unit customer rate |
| `cost_ex_tax` | O | decimal | Cost recorded in billing system (if tracked) |

**Heuristic detection patterns:**

| Canonical Field | Patterns to try |
|---|---|
| `customer_id` | `customer id`, `client id`, `account id`, `cust id`, `cust_id`, `account no` |
| `billing_period_start` | `period start`, `billing from`, `service start`, `from date` |
| `billing_period_end` | `period end`, `billing to`, `service end`, `to date` |
| `our_service_id` | `service id`, `our service`, `internal id`, `product id`, `service ref` |
| `revenue_ex_tax` | `revenue ex`, `ex gst`, `charge ex`, `amount ex`, `net revenue`, `sale ex` |
| `customer_name` | `customer name`, `client name`, `account name`, `customer` |
| `cost_ex_tax` | `cost ex`, `cogs`, `cost ex gst`, `wholesale`, `supplier cost` |

### Source Type: `rate_card`

Supplier rate card — expected per-service costs for a given period.

| Canonical Field | R/O/D | Type | Description |
|---|---|---|---|
| `service_type` | R | string | Service category this rate applies to |
| `expected_cost_ex_tax` | R | decimal | Expected charge per service per period, ex tax |
| `effective_date` | R | date | Date this rate became effective |
| `supplier_service_id` | O | string | Specific service ID if rate is service-specific |
| `speed_pack` | O | string | Speed tier (e.g. 25/5, 50/20, 100/20) |
| `expiry_date` | O | date | Date this rate expires (open-ended if absent) |
| `notes` | O | string | Notes on rate conditions or exceptions |

---

### Source Type: `service_map`

Maps supplier service IDs to our internal service IDs and customer IDs. Required for
reconciliation when supplier and billing systems use different identifiers.

| Canonical Field | R/O/D | Type | Description |
|---|---|---|---|
| `supplier_service_id` | R | string | Supplier's identifier |
| `our_service_id` | R | string | Our internal identifier for the same service |
| `customer_id` | O | string | Customer this service belongs to |
| `service_type` | O | string | Service category |
| `active` | O | boolean | Whether the service is currently active |

### Derived Fields (output only — never sourced from input CSVs)

| Canonical Field | D | Type | Derived from | Description |
|---|---|---|---|---|
| `match_status` | D | enum | reconciliation logic | `matched`, `invoice_only`, `sales_only`, `duplicate`, `amount_mismatch` |
| `variance_abs` | D | decimal | `amount_ex_tax - revenue_ex_tax` | Absolute difference between supplier charge and customer revenue |
| `variance_pct` | D | decimal | `variance_abs / amount_ex_tax` | Relative variance as proportion of invoice amount |
| `direct_margin_ex_tax` | D | decimal | `revenue_ex_tax - amount_ex_tax` | Raw direct margin per line |
| `direct_margin_pct` | D | decimal | `direct_margin_ex_tax / revenue_ex_tax` | Direct margin as proportion of revenue |
| `rate_variance_abs` | D | decimal | `amount_ex_tax - expected_cost_ex_tax` | Difference between actual and expected supplier cost |
| `exception_severity` | D | enum | threshold config + variance magnitude | `high`, `medium`, `low` |
| `source_file_hash` | D | string | SHA-256 of source file at load time | Proves source file was not modified |

## Mapping Validation Rules

When `validate_inputs.py` loads a `mapping.yaml`:

1. Every **required** canonical field for the declared `source_type` must have a mapping entry.
   - Fail with: `Missing required mapping: <canonical_field>`
2. Every mapped source column must exist in the CSV header.
   - Fail with: `Mapped column not found in CSV: <source_column> (for canonical field <canonical_field>)`
3. Required numeric fields (`amount_ex_tax`, `revenue_ex_tax`, `expected_cost_ex_tax`) must
   parse as decimal after stripping currency symbols and commas.
   - Fail with: `Non-numeric values in required decimal field: <canonical_field>`
4. Required date fields must parse with at least one common format (ISO, AU DD/MM/YYYY, US MM/DD/YYYY).
   - Fail with: `Unparseable date values in required date field: <canonical_field>`
5. Source files must not be modified at any point — validate against hash recorded at load.

---

## Ambiguity Protocol

When heuristic detection cannot confidently map a required field:

- The validator does **not** silently pick a candidate.
- It prints: `Cannot map required field '<canonical_field>'. Candidates: [col_a, col_b]. Add correct mapping to mapping.yaml.`
- Analysis halts until the mapping is confirmed.

When a required field has no candidates at all:

- The validator prints: `Required field '<canonical_field>' has no candidate columns. Check source file or mapping.yaml.`
- Analysis halts.
