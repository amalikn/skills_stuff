## Licence finding

The four office folders of github.com/anthropics/skills (`skills/pptx`, `docx`, `xlsx`, `pdf`) each hold a `LICENSE.txt` that is the unmodified Apache License 2.0 text (checked by the lead with the
GitHub API on 2026-11-12). The pptx research read the commit message "Move Office skills to the Apache 2.0 license (#2146): docx, pdf, pptx and xlsx now use the same Apache 2.0 license as most other
skills here", dated 2026-11-06. The repo README says the skills are "provided for demonstration and educational purposes only". GitHub shows no licence at repo level. Copying is permitted under Apache
2.0 with the licence text and notices kept and changes marked; the `LICENSE.txt` copyright line is the unfilled template; no NOTICE file was found in the docx folder. Earlier copies of these skills
carried a proprietary licence, so copy only from a commit on or after 2026-11-06 and re-read each script's header. The locally installed `doc`, `spreadsheet` and `pdf` skills (OpenAI/Codex lineage)
carry an Apache-2.0 `LICENSE.txt` (read locally). openai/skills has no slides or spreadsheet skill under `.curated` (only `pdf`, `openai-docs`, `notion-*`).

## PowerPoint

Sources: anthropics/skills `skills/pptx` (SKILL.md plus `scripts/{thumbnail.py, add_slide.py, clean.py, office/validate.py, office/soffice.py}`), pptxgenjs 4.0.1 (MIT, last release 2025-06, 310 open
issues), python-pptx 1.0.2 (MIT, last release 2024-08), OfficeCLI (Apache-2.0, 33k stars, not read in depth), slide-wright (MIT; preview-then-approve flow), frontend-slides (MIT; phased workflow with
density modes).

Learnings (VP unless stated; source: the Anthropic pptx SKILL.md and PptxGenJS docs):

1. Create with pptxgenjs; edit templates by unzip, edit XML, zip; read with markitdown.
2. `LAYOUT_16x9` is 10 by 5.625 inches and `LAYOUT_WIDE` is 13.3 by 7.5; set the layout before adding slides; off-canvas coordinates are written, not clamped.
3. Hex colours have no `#` and no 8-digit alpha (both corrupt the file); transparency is 0 to 100 on fills, opacity 0 to 1 on shadows; never share one options object across add calls (pptxgenjs
   mutates it); a negative shadow offset corrupts.
4. Keep charts native with `addChart`; set title, data labels, `chartColors`, quiet gridlines; stacked bar `dataLabelPosition: outEnd` corrupts; a combo chart with a secondary axis needs two entries
   in both `valAxes` and `catAxes`.
5. Always run `validate.py` after `writeFile`: pptxgenjs can emit chart XML that LibreOffice and python-pptx accept but PowerPoint refuses, so a LibreOffice render passing proves nothing about
   PowerPoint.
6. Speaker notes: `slide.addNotes()`, never an on-slide text box. python-pptx has `slide.notes_slide.notes_text_frame` (VS).
7. Alt text: `addImage` has `altText`. Screen readers read in the order elements were added, so add in reading order (Microsoft accessibility page, VP).
8. Masters: `defineSlideMaster()` makes real layouts; use them for branding rather than per-slide shapes.
9. Fonts that render true in LibreOffice QA: Arial, Calibri, Cambria, Times New Roman, Courier New, Bookman Old Style, Century Schoolbook; Georgia, Trebuchet, Garamond, Consolas, Aptos are unreliable;
   leave about 10% slack.
10. QA: `soffice --headless --convert-to pdf`, then `pdftoppm -jpeg -r 150`, inspect every image; check overflow, then overlaps, gaps under 0.3 inch, margins under 0.5 inch, low contrast. Bare
    `soffice` hangs in sandboxes (wrap it with a timeout).
11. Sizes: title 36 to 44 pt, body 14 to 16 pt, captions 10 to 12 pt (Anthropic's guidance; a convention, not a standard). Their style rules (no accent lines under titles, vary layouts) are one
    vendor's taste.
12. Edit mode: do all add, delete and reorder first, content edits after; parse OOXML with defusedxml, not ElementTree; python-pptx cannot duplicate slides and `text_frame.text` collapses run
    formatting.

Pitfalls: literal bullet characters double up (use `bullet: true`, `breakLine` on every item but the last); `letterSpacing` is ignored (`charSpacing`); gradients unsupported; first render usually has
a few real defects, fix them, re-render only changed slides, then stop; template slots are not source items (delete the whole unused group, then check for orphaned visuals, and grep for placeholder
leftovers). UN: python-pptx has no alt-text API (needs an XML `descr` edit) and no animation or SmartArt creation. Open: automated overflow and overlap checks do not exist beyond visual inspection and
`validate.py`; PowerPoint AppleScript export not researched.

## Word

Sources: anthropics/skills `skills/docx` (SKILL.md 6.8 KB; scripts `office/validate.py`, validators `base.py`, `docx.py`, `redlining.py`, `merge_runs.py`, `accept_changes.py`, `comment.py`,
`soffice.py`, the XSD set), docx-js 9.15.3 (MIT), python-docx 1.2.0 (MIT; comments added 2025-06), docxtpl 0.20.2 (LGPL-2.1), docx-templates 4.15.0 (MIT), pandoc 3.14 (GPL-2.0, external tool),
Microsoft "Make your Word documents accessible".

Learnings (VP):

1. Generate with docx-js; edit by unzipping and editing `word/document.xml`; validate the rezip with `validate.py out.docx --original doc.docx`.
2. Word splits visible text across many runs; `merge_runs.py` coalesces them; do not pretty-print `document.xml`.
3. Tracked changes are validated with `--author` and `--original`; `accept_changes.py` (LibreOffice) makes a clean copy; `comment.py` adds comments and replies.
4. docx-js footguns: page size defaults to A4; landscape needs portrait dimensions plus an orientation flag; tables need `columnWidths` and a cell `width` in DXA (percentage breaks in Google Docs);
   shading must be `ShadingType.CLEAR` (SOLID renders black); bullets come from a numbering config with `LevelFormat.BULLET`, never a literal bullet; `ImageRun` needs `type:`; never use `\n` (use
   separate Paragraphs); a TOC needs built-in `HeadingLevel` or a style with `outlineLevel`; no table as a horizontal rule; `PositionalTab` for dot leaders.
5. QA loop: `soffice --convert-to pdf`, `pdftoppm -jpeg -r 100`, look at the pages (LibreOffice, not Word's engine).
6. Files from external parties are untrusted: strip symlink entries when unzipping.
7. Pandoc `--reference-doc` copies styles, margins, page size, header and footer; make it with `pandoc -o custom-reference.docx --print-default-data-file reference.docx` and edit only styles;
   `--track-changes=accept|reject|all`.
8. Accessibility: built-in title, subtitle and heading styles, alt text on visuals, header rows on tables.
UN: a TOC field made by docx-js or python-docx is empty until Word updates it; fonts missing on the render machine are substituted so page breaks can differ; python-docx has no TOC or field update.
Open: Word's own PDF engine on macOS versus LibreOffice with a font-embedding check; reliable headless TOC refresh; business-writing rules need plainlanguage.gov or the UK GDS style guide. Licence
  caution: docxtpl is LGPL; docxtemplater has paid modules.

## Excel and PDF

Sources: anthropics/skills `skills/xlsx` (SKILL.md, `scripts/recalc.py`, `scripts/office/soffice.py`, `validate.py`) and `skills/pdf` (SKILL.md, `forms.md`, `reference.md`, 8 scripts incl.
`convert_pdf_to_images.py`), openpyxl 3.1.5 (MIT), XlsxWriter 3.3.1 (BSD-2), SheetJS CE (Apache-2.0; styling pushed to Pro), ExcelJS 4.4.0 (MIT), WeasyPrint 70.0 (BSD), Playwright 1.65.1 (Apache-2.0),
PyMuPDF (AGPL or commercial), pypdf 7.0.1 (BSD-3), pdfplumber 0.11.10 (MIT), reportlab 5.1.0 (BSD), ocrmypdf 17.14.1 and pikepdf (MPL-2.0).

Learnings (VP unless stated):

1. Formulas, never Python-computed totals. openpyxl stores formulas with no cached values; `data_only=True` reads None until recalculated; `data_only=True` then save is destructive.
2. Recalculate with LibreOffice (`recalc.py`, default 30 s) and read its JSON (`status`, `total_formulas`, `total_errors`, `error_summary`); an `errors_found` result exits 0, so check the JSON, not
   the exit code. A green recalc proves formulas evaluate, not that they are right (off-by-one ranges): test two or three formulas first.
3. Use Excel-2007-era functions (SUMIFS, INDEX/MATCH, IFERROR); TEXTJOIN, CONCAT, IFS, SWITCH, MAXIFS need `_xlfn.`; avoid XLOOKUP, FILTER, SORT, UNIQUE, SEQUENCE (spill arrays truncate silently); a
   lowercased formula after recalc signals a parse failure. Merged cells: write the top-left anchor only; `.xlsm` needs `keep_vba=True`; quote sheet names with spaces.
4. Financial-model conventions: blue text inputs, black formulas, green cross-sheet links, red external links, yellow key assumptions; percentages as fractions; years as text; units in headers; guard
   zero denominators; no hardcodes inside formulas. Editing an existing file: its conventions override these; write only to input cells; document assumptions and sources beside the cell.
5. XlsxWriter writes new files only and stores 0 as an uncached formula result unless `write_formula(..., value)` is given; route: XlsxWriter to create, openpyxl to edit, then LibreOffice recalc.
6. WeasyPrint: PDF/A and PDF/UA variants are generated but "not guaranteed to be valid"; tagging is a flag (`--pdf-tags`); `break-before/after/inside` supported. Playwright `page.pdf`: `tagged`
   (v1.42+) and `outline` default false, `prefer_css_page_size` defaults false (content is scaled to paper unless set), headers and footers need `display_header_footer`.
7. PDF render check: `pdftoppm -png`, inspect every page, zero visible defects is the gate; never use Unicode sub- or superscripts in reportlab built-in fonts (black boxes); text extractors are not
   fidelity checks; pdfplumber works best on machine-generated PDFs; ocrmypdf outputs PDF/A by default.
UN: the exact list of what openpyxl drops on load and save; accessibility checker choice (veraPDF). Do not bundle PyMuPDF without accepting AGPL. The openai/skills `pdf` skill is Apache-2.0 prose
(render with `pdftoppm`, create with reportlab) with nothing to copy.

## Audience and structure

Sources read: anthropics/skills `doc-coauthoring` (VP), escherize/pyramid-principle-skill (no licence, 1 star; VP), dungnotnull/communication-presentation-coach-agent-skill (MIT, 4 stars; VP),
barbaraminto.com (VP), duarte.com Resonate page (VP), workingbackwards.com PR/FAQ (VP), Wikipedia Stakeholder analysis (VS). Landscape (from the cross-cutting report): frontend-slides (MIT, 32k
stars), huashu-design (MIT, 29k, unread), dashi-ppt-skill (AGPL-3.0, avoid copying), hands-on-deck (MIT; has evals and tests), ComposioHQ and VoltAgent awesome lists (discovery only),
vercel-labs/skills (MIT; packaging reference).

How existing skills decide shape from audience:

- `doc-coauthoring`: stage 1 asks five meta-questions (document type, primary audience, desired impact on the reader, template, constraints); a context info-dump; 5 to 10 gap questions; each section
  built by brainstorming 5 to 20 options and curating; stage 3 tests the draft with a fresh reader that has no context.
- pyramid-principle skill: governing thought in one sentence, SCQA, answer first, MECE groups, action titles, one message per slide.
- coach skill: its intake blocks if audience or purpose is unknown; picks at least two frameworks by purpose and format; scores a script; acts after a draft exists.

Rules (VP unless stated): read audience and impact first; test the draft on a context-free reader; block drafting if audience or purpose is unknown; state the governing thought in one sentence; SCQA
with Situation limited to what the reader already agrees with; lead with the answer and group points MECE; action titles, one message per slide; make the audience the hero and the presenter the mentor
(Duarte); ask what is at stake for the audience; do not equate more with better, restrict length (Amazon); work backwards from the customer outcome with a press release and FAQ; stakeholder
power-interest grid (VS). UN: Big Idea (Knaflic), Who/What/How, SBAR (Situation, Background, Assessment, Recommendation or Request), Made to Stick's SUCCESs, BLUF, jobs-to-be-done.

Design guidance (cross-cutting report): text contrast at least 4.5 to 1 (3 to 1 for large text, 18 pt or 14 pt bold), non-text cues 3 to 1 (WCAG 2.2, VP); never colour alone for status (WCAG 1.4.1,
VP); Okabe-Ito colour-blind-safe palette (UN, page not read back); Tufte (data-ink) and Few (avoid pie and 3-D, table when exact values matter) (UN, books); PDFs need tags, language, reading order,
alt text, and GOV.UK prefers HTML to PDF (UN). Failure modes of generated decks: text-only bullet slides, topic titles not conclusions, overflow visible only in a render, default-styled charts, colour
as the only signal, orphaned template shapes, unlabelled or unsourced figures, hand-edited exports that drift from the source, text pasted as images.

## The gap this pack fills

No public skill found maps audience and objective to a choice of form, nor requires business, technical, financial and management views on every item. Existing office skills are file-format and
visual-design guides; `doc-coauthoring` is the closest on audience questions; the pyramid and coach skills act on structure or on an existing draft. This is a negative finding from the 2026-11-12
survey of anthropics/skills, openai/skills, GitHub search and the awesome lists' metadata (lists not read in full).

## Code worth adopting

Apache-2.0, copy with licence text, notices kept and changes marked: Anthropic `skills/pptx/scripts` (`office/validate.py` most valuable, `office/soffice.py`, `thumbnail.py`, `add_slide.py`,
`clean.py`); `skills/docx/scripts` (`validate.py`, `validators/*`, `merge_runs.py`, `accept_changes.py`, `comment.py`, `soffice.py`, the XSDs); `skills/xlsx/scripts` (`recalc.py`,
`office/soffice.py`); `skills/pdf/scripts/convert_pdf_to_images.py`; the locally installed `doc/scripts/render_docx.py`. Check each script's header and any THIRD_PARTY_NOTICES before copying. MIT
libraries are used as dependencies: docx-js, python-docx, pptxgenjs, openpyxl, XlsxWriter, ExcelJS. Pandoc (GPL-2.0) and LibreOffice are called as external tools only. Avoid: PyMuPDF without AGPL
acceptance, dashi-ppt-skill (AGPL-3.0), docxtpl (LGPL linking) unless the obligation is accepted.
