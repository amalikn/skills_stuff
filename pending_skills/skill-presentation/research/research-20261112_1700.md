## The profitability work: workbooks and mind maps

Surveyed 2026-11-12 in two APN projects (carrier and fibre profitability); the operator named them as the most extensive spreadsheet work (operator, 2026-11-12). Local files read, not external research.

Workbooks (xlsx): one file per basis or scenario with the basis in the file name and a timestamp (`profitability-by-speed-tier-202604-base-oac-ovc-<YYYYMMDD_hhmm>.xlsx`, `profitability-enriched-...`, a vs-retail comparison
and what-if rate-card scenarios). Generator scripts: `opticomm_export_speed_tier_profitability.py` (basis-labelled base or `--basis enriched`), `gen_profitability_vs_retail.py` (OAC wholesale cost against APN retail
pricing, default Apr 2026 plus Jul 2026 rate-card what-if), `generate_hyp_pricing_report.py`. Conventions seen: snake_case data columns; a top block with title and the month; an "Exclusions & Assumptions" section
(rows 11 to 20) with one labelled assumption per row; a column glossary where derived columns are annotated `[FORMULA] = ...` with their meaning and sign (for example delta_profit positive means improvement under the
what-if); scenario workbooks hold baseline, hypothetical and delta columns; costs split into direct (OAC, OVC) and shared infrastructure pools (backhaul, internet, data centre) shown as percent of revenue; one canonical
source file named in AGENTS.md (the older sibling is explicitly not canonical). Sheets per file are few (one sheet per month in the files read); the audience is commercial and finance readers.

Mind maps (markdown): `markmap`-compatible Markdown (headings and bullets that render as a mind map) kept in `docs/reports/mindmaps/`. Generators: `generate_profit_mindmap-generic.py` (profit and loss by any grouping
dimension, schema auto-detected for both projects, several dimensions in one pass, parquet input, output to `docs/reports/mindmaps/<name>.md` and stdout), `generate_enriched_mindmap.py`,
`generate_l2_vs_l3_mindmap.py`, `generate_hyp_mindmap.py` and `generate_hyp_mindmap_3way.py` (exec-friendly vs-comparison for three scenarios: L2 baseline, L2 new pricing, new pricing plus negotiated cost reductions).
Shape of a data mind map (enriched, 2026-04): an H1 that states the headline in one line (margin, profit per month, status icon); a blockquote with the base facts and the cost basis; a legend line (tick at or above
the portfolio average margin, warning below a threshold); `---` rules; H2 sections with status icons (Snapshot, Strong Performers, below-threshold groups); H5 nodes per group with the icon, the group name, its margin and
the difference to the portfolio average in points; bullets under each node with services, revenue, cost split and bolded profit. Hand-written maps (`target-mindmap.md`) follow the same markmap form: H1 project, H2
sections (The Problem, the stakeholder's questions, Work Plan), H3 items, bullets as evidence, bold for the headline figure. A hard rule in the vocus project (added 2026-06-05): during every coherence sweep, move
superseded dated report files (md, xlsx, csv with an older `_YYYYMMDD_HHMM` on the same slug) into an `archive/` subfolder beside them (profitability, scenarios, mindmaps), keep only the latest of each report type in the
active folder, update the reports README, SCRATCHPAD anchors and routing, and add a CHANGELOG entry; exceptions: static anchors, audit and reconciliation files, unique-slug files.

Renderer (verified locally 2026-11-12 from `~/.vscode/extensions/gera2ld.markmap-vscode-0.3.1/package.json` and its readme): the VS Code extension `gera2ld.markmap-vscode` ("Markmap", MIT, repository gera2ld/markmap-vscode; versions 0.3.0 and 0.3.1 are installed). Commands: `Open as markmap` (`markmap-vscode.open`, from the Command Palette, the Explorer context menu or the editor title-bar button), `Toggle the active node` and `Toggle the active node recursively`; settings `markmap.defaultOptions` and `markmap.customCSS`; themes and layouts in front matter; export to HTML, SVG or PNG; works offline. The projects' READMEs describe the maps as "Markmap" mindmaps.

Implication for the skill: the mind map is a first-class deliverable form (a one-glance executive view of a decision or a data breakdown, readable as plain markdown and rendered by markmap), the profitability
workbook has a settled convention to follow, and the archive rule is an operator rule for dated outputs.

## Audience methods, primary sources

Corrections to round 1 (VP unless stated):

1. Minto's framework is named Situation, Complication, Question (SCQ), per the author's page; "SCQA" is not supported by that page. State the exact framework name when citing.
2. Knaflic's Big Idea is one complete sentence with a point of view and what is at stake (credited to Duarte's Resonate); each slide and the whole piece need one. Storyboard before software: outline
   on paper first, get the outline agreed, start from the audience and what they must know or do; tell the story in three minutes without slides. (storytellingwithdata.com posts of 2014-02.)
3. Duarte: the audience is the hero and the presenter the mentor, with conflict and resolution. The "sparkline" terms were not on the page read (UN).
4. SBAR is Situation, Background, Assessment, Recommendation; start with the situation; never skip the recommendation or request. (AHA TeamSTEPPS module; the AHRQ page returned 403.)
5. Amazon PR/FAQ: write the press release (a one-sentence heading naming the product in the customer's words, a one-sentence subheading naming the customer and the benefit) and a plain-words FAQ
   first, working backwards from the customer; the page also sells a course, so treat it as vendor material.
6. BLUF puts the main point first, in active voice (Wikipedia essay-like page, VS; the Army source unread, UN). Knaflic's own example puts the Big Idea last and then suggests leading with it, so
   "always BLUF" overstates her.
7. Plain-language guidance (Digital.gov): write for the specific audience and test for understanding with readers.
Still UN: Knaflic's who, what, how; Made to Stick's six traits by name; Amazon's six-page narrative rules.

## Word, PDF and table of contents on macOS

- docx2pdf drives Word through JXA and requires Word installed (VP, README). Scripted Word PDF export triggers file-access permission dialogs per file, even with Full Disk Access, so a first run needs
  a person to click Allow (VS, a forum thread of 2022 to 2023): do not promise unattended runs.
- A TOC field generated by docx-js or python-docx has no entries until an application evaluates it; Word asks on open when `w:updateFields` is true in settings.xml (VS); `w:dirty` alone did not update
  it in one report (VS). The VBA `TablesOfContents(1).Update` refreshes the whole TOC; the Word for Mac AppleScript verb was not confirmed (UN). No tested script that updates a TOC and exports PDF on
  Word for Mac was found.
- LibreOffice: Carlito is metric-compatible with Calibri, so line breaks should match; missing fonts fall back silently (VS). Anthropic's docx skill renders through LibreOffice for QA, not for a TOC
  refresh (VP).
- docx-js rules (VP, Anthropic docx SKILL.md): built-in `HeadingLevel` for TOC headings (custom styles need `outlineLevel`), A4 default, table `columnWidths` plus cell widths in DXA,
  `ShadingType.CLEAR`.

## Accessible PDF and checkers

- veraPDF (dual GPLv3+ or MPLv2+; v1.30.4 on 2026-11-10) runs headless: `verapdf -l` lists profiles (ua1, ua2, wt1a, wt1r); `-f ua1 --format json file.pdf`; run it as an external CLI. Exit codes UN
  (read `--help`). (VP, docs.verapdf.org)
- Playwright `page.pdf`: `tagged` and `outline` both default to false (since v1.42): set them. WeasyPrint 70: `--pdf-variant pdf/ua-1`, `--pdf-tags`; correct HTML structure, `<title>` and `lang` are
  the main constraints. (VP)
- Word: Review, Check Accessibility; built-in heading styles, alt text, a header row on simple tables. PAC is Windows only and has no documented CLI (VS). Machine checks are partial: meaning of alt
  text and reading order need a human (UN as to exact coverage). Not read: WCAG 2.2 spec, PowerPoint checker page. Word Save as PDF versus Print to PDF tag behaviour: UN.
- community-access/accessibility-agents (MIT, 445 stars, pushed 2026-11-09) has a PDF accessibility skill (Matterhorn 31 checkpoints); body not read.

## Office code and licences

- anthropics/skills `pptx`, `docx`, `xlsx`, `pdf`: each LICENSE.txt is the unmodified Apache-2.0 text (11,357 bytes; copyright line left as the template); the README says "These are also open source
  (Apache 2.0)" (VP). No per-file headers, no NOTICE, no third-party file in any folder. The `office/` folder is byte-identical in pptx, docx and xlsx. 39 XSD files per skill (ISO 29500-4:2016, ECMA,
  mce, Microsoft) carry no licence text, and their redistribution terms were not read (UN): depend on them by reference for a personal skill, or take them from the standards bodies.
- Script notes (VP): `thumbnail.py` needs PIL, defusedxml, soffice and pdftoppm; `recalc.py` starts LibreOffice with a temporary profile and an injected macro and uses `gtimeout` on macOS only if
  installed, otherwise it can hang; `validate.py` tracked-change checks need `--original`; the pptx helpers detect, they do not repair; `soffice.py` has a Linux sandbox shim, untested on macOS; the
  pdf scripts have no docstrings.
- OfficeCLI (iOfficeAI, Apache-2.0 with NOTICE, v1.0.160 on 2026-10-30, a compiled binary): its skills are readable as patterns. A different project with the same name exists (MIT); do not confuse
  them.
- Personal use: copying Apache-2.0 code is allowed with the licence text kept and changes marked; GPL and AGPL tools (veraPDF, PyMuPDF) are used as external tools or for personal work only.
